# Dino Code v0.1 Spec —— 终端 AI 对话助手

## 背景

Dino Code 是一个运行在终端的 AI 编程助手，最终形态类似 Claude Code。v0.1 只证明一件事：核心对话链路跑通——用户在终端提问，程序调用大模型 API，回复以流式（SSE）实时逐字呈现，多轮对话有记忆。

本步不做任何 agent 能力（工具调用、文件操作、代码编辑），纯对话。

只支持 **OpenAI 协议**，覆盖一切 OpenAI 兼容端点（OpenAI、DeepSeek、千问、智谱、Kimi、vLLM 等）。

视觉主题：**绿色可爱 mini 恐龙**，贯穿启动画面、提示符与等待指示。

## 目标用户

- 开发者本人：日常在终端里向 OpenAI 兼容模型（DeepSeek / 千问 / 智谱 / OpenAI 等）提问、连续追问
- 偏好终端工作流、需要自由切换后端地址的开发者

## 能力清单

1. 终端启动后进入绿色恐龙主题的交互式对话界面
2. 用户输入问题，模型回复以 SSE 流式实时逐字呈现，不是等全部生成完才返回
3. 多轮对话：每次请求携带当前会话完整历史
4. 会话持久化到磁盘，启动时自动恢复最近一次会话
5. 支持开启新会话，旧会话保留在磁盘上
6. 走 OpenAI 协议，后端地址可指向任意 OpenAI 兼容端点（OpenAI / DeepSeek / 千问 / 智谱 / vLLM 等），改配置即可切换
7. Provider 层为统一流式接口，终端层不感知后端差异
8. 推理模型（DeepSeek reasoner / 千问思考等）的思考流实时流式显示，视觉上与正文明确区分
9. 配置支持 YAML 文件与环境变量两种来源，配置文件可省略，全环境变量即可启动
10. 认证凭据优先取环境变量，避免明文落盘
11. 最大输出长度可在运行时用命令调整（预设档位或自定义数值），调整随会话持久生效
12. 生成过程中可中断本轮，已流出的内容保留并计入历史
13. 运行时错误（认证失败、限流、网络异常、上下文超限）友好提示且不退出程序
14. 配置文件错误在启动时明确报错并退出
15. 输入具备历史记录与行编辑能力

## 非功能要求

- Java 21（LTS）+ Maven 构建
- 单一可执行产物交付（fat jar / 启动脚本）
- HTTP 用平台自带能力，不引入各家官方 SDK
- 回复以纯文本呈现，不做 Markdown 渲染
- 单元测试覆盖：配置解析、会话存取、SSE 解析
- 可离线验证流式链路：对 mock 端点跑通完整流程，不依赖真实 key，可进 CI
- 配置与用户数据只存于用户主目录，不落项目目录

## 设计骨架

六个模块，依赖单向向下：

```
终端交互层（输入循环 / 渲染 / 命令 / 中断）
        ↓
组装入口（加载配置 → 建 Provider → 恢复会话 → 运行主循环）
   ↓           ↓              ↓
配置加载      会话持久化      适配层
（YAML/环境变量（会话存 /      （统一流式接口 +
 解析、凭据）  读 / 恢复）       OpenAI 适配器）
                     ↓
          核心模型（消息 / 历史 / 统一流式事件）
```

关键架构决策：

- **统一流式事件**：把 OpenAI 兼容端点的流收敛为四种事件——思考增量、正文增量、结束、错误；终端层不感知后端差异
- **同步阻塞流式 + 虚拟线程**：流的读取在虚拟线程上以普通循环进行；中断 = 中断线程，语义简单可靠
- **单一 OpenAI 适配器**：解析 OpenAI 的 `data:` 行 + 结束哨兵；推理模型的思考流（`reasoning_content`）映射为思考增量
- **思考不进历史**：思考/推理内容只渲染到终端，不写入历史、不回传（省 token）
- **完整历史每轮全量发送**：不做裁剪、压缩、摘要；上下文超限由运行时错误提示兜底

## Out of Scope

- 工具调用、文件操作、代码编辑等 agent 能力
- Markdown 渲染
- 会话列表、会话选择界面（多会话只自动恢复最近一条）
- 自动重试、失败退避
- 历史自动裁剪 / 压缩 / 摘要
- 系统提示词、模型人格定制（"恐龙味"只体现在 UI 层，不影响模型回复风格）
- **Anthropic Claude 协议及其 extended thinking**（只用 OpenAI 协议）
- 运行时切换后端或模型（只能改配置后重启）
- 会话云同步、多机共享

## 完成定义

checklist.md 中所有验收项逐条可勾选且全部通过；其中端到端验收必须用真实 OpenAI 兼容后端（如 DeepSeek）跑通。
